# 探原 · SourceQuest

面向 DeepSeek Harness（DSH）的可追溯网络研究插件。

根据任务自动选择搜索源、模型和读取工具，围绕证据缺口开展有预算的研究，交付能够回到原文的答案与研究记录。首发优先提供 DSH 原生体验，之后扩展 MCP、CLI 和其他客户端。

> **项目状态：开发中。** 在 DSH 0.2.2-rc.5 已接通首条研究链路。`net_research` 通过宿主搜索源收集候选，读取最多三篇公开 HTTPS 页面，并返回有原文链接的引文。

## 试用首条研究链路

在启用探原的 DSH 会话中，可以说「用 `net_research` 搜索 DSH Cordis 的工具注册方式，优先返回原文引文」。也可以直接提供公开 HTTPS URL。单次可传到三个查询或三个显式 URL，最多读取三个页面。遇到查询失败，工具保留已取得的来源与引文，并附上失败原因。

引文附最终 URL、抓取时间、规范化正文的 SHA-256 和字符区间。当前预览结果随工具调用返回，持久快照、自动补查和后台任务仍在路线图中。

## 计划提供的能力

- **自动路由**：根据任务、来源能力、可调用状态、上下文和预算选择工具与模型，保留手动指定。
- **有界研究**：问题拆解、检索、原文读取、证据缺口检查、定向补查与复核。
- **证据追溯**：关键事实关联实际读取的原文、时间、版本与定位，区分事实、推断和未解决问题。
- **可靠任务**：进度、预算、取消、持久检查点与恢复。
- **原生体验**：DSH 内的来源、策略、任务与证据面板，按需暴露工具。
- **可选执行器**：动态网页、浏览器、文档解析和批量采集通过适配器接入。

## 设计原则

1. 复用宿主的搜索、模型、凭据和任务接口；已有搜索管理器可以作为集成伙伴。
2. 同一任务统一预算与来源计数，识别不同连接器背后的相同服务，避免重复请求。
3. 根据实际能力降级；没有凭据、额度未知或来源失败时如实记录。
4. 研究质量通过真实任务、原文支撑与回归评测验证；引用数量和报告长度不能单独证明质量。
5. 研究核心与宿主适配分离，逐步扩展其他客户端。

## 首发范围

首期采用单仓库、单主包、内部模块化，先完成 DSH 中的一条可验收闭环：

```text
任务 → 来源与模型选择 → 检索与原文读取 → 缺口检查 → 有限补查 → 带证据的结果
```

核心模块不依赖 DSH，通过接口取得搜索、读取、模型、任务与产物存储能力。DSH 适配负责宿主服务、原生界面和生命周期。可选运行组件按需启用。

## 开发验证

使用 Node.js 24，从源码运行 `npm ci`、`npm run check` 和 `npm test`。如需在 DSH 0.2.2-rc.5 中试装，先用 `npm pack` 导出构建包，再按[隔离验收步骤](docs/COMPATIBILITY.md#隔离-profile-验收)验证安装、执行和移除。
