# 验收、评测与发布门槛

本文件定义验证体系与发布门槛。核心契约、B1–B22 场景（[acceptance-b1-b22.test.mjs](../test/acceptance-b1-b22.test.mjs)）、50 题分层离线评测（[eval-50.mjs](../benchmark/eval-50.mjs)）及端到端挂载卸载（[complete.e2e.test.mjs](../test/e2e/complete.e2e.test.mjs)）已接入自动化验证；需第三方凭据/在线配额/本地重型二进制的场景按真实条件标记受阻或未实测。

## 1. 验证层级

| 层级 | 验证内容 | 自动化策略 |
|---|---|---|
| Unit | 状态、预算预留、去重、路由硬约束、定位、schema/迁移 | fake clock、合成数据与 ports；验证行为与失败，不镜像实现 |
| Contract | DSH SDK、连接器、worker、receipt 和错误语义 | 锁定类型/fixture；不同 adapter 通过同一契约套件 |
| Integration | bundle、工具/scope、RPC/UI、jobs、storage、重载 | 隔离 DSH_HOME/profile；与生产端口、会话和浏览器目录分开 |
| Evaluation | 用户目标、覆盖、引用/事实正确性、时间与消耗 | 显式触发在线任务，固定题目与参考；保留失败 |

文档更新只做链接、格式与一致性检查；不为低影响文案增加实现测试。业务改动完成必要检查后，只有出现新改动或疑点才扩大测试。

## 2. v0.1 必须验证的场景

| 场景 | 预期结果 | 失败是否阻断 |
|---|---|---|
| 基础安装，无 Magpie/Tool Ultra | 已配置的宿主搜索/读取可用，缺少来源明确诊断 | 是 |
| 已有搜索管理器与个人预设 | 不修改默认来源/模型，无递归聚合或重复工具 | 是 |
| 原生 Provider 显式启用与卸载 | 按配置选中，禁用时回到宿主路径。验证既有管理器共存或明确互斥 | 是 |
| 多查询一条失败 | 探原研究工具保留成功查询与失败原因，取消传递到所有未结束子调用 | 是 |
| 静态读取出站与重定向策略 | 用隔离 fixture 验证地址策略和实际连接一致，拒绝的目标不会进入后续执行阶梯 | 是 |
| 长正文与 Artifact | 输出遵守 token 上限，引用可按所有者读取。失去存储时明确提示截断 | 是 |
| 只给 URL | 直接读取；返回实际来源与正文/定位 | 是 |
| 日期、域名、版本约束 | 支持则保留；不支持明确拒绝/选择允许的来源 | 是 |
| 来源关闭/失去凭据 | 所有入口遵守开关；不沿缓存认证状态继续发请求 | 是 |
| 手动模型/执行器不可用 | 显式错误；仅在允许 fallback 时切换并记录 | 是 |
| provider 429/超时/认证错误 | 分类型处理、有限重试/冷却、保留成功部分 | 是 |
| 短公告、长登录页、JS 空壳 | 按有效内容与任务判断；不由长度/200 单独决定 | 是 |
| PDF/截图等未支持输入 | 明确不支持或交给已验证适配，不能返回噪声冒充正文 | 是 |
| 并发预算与补查 | 不突破可保证的上限，未知下游消耗如实显示 | 是 |
| 预算耗尽、仍有问题待查 | partial 含具体未解决问题与证据 | 是 |
| 取消、迟到结果与重载 | 确认资源释放后终止；旧 run 不覆盖新状态 | 是 |
| 重启/存储失败/损坏快照 | interrupted 或明确错误；不伪造完成，已验证成果可恢复 | 是 |
| 不同会话读取/取消任务 | 服务端拒绝越权；任务 ID 不是授权凭据 | 是 |
| 缓存和导出 | 私有/公开分开；受限目录/数据不进入公共产物 | 是 |
| 关键事实引用 | 回到实际读取的原文；不支持则标推断/未知 | 是 |
| UI 安装→诊断→研究→结果→取消/恢复 | 在浏览器实测；远程入口认证链不被绕过 | 是 |
| 关闭/卸载/升级回退 | 工具、订阅与进程清理；数据保留/迁移规则明确 | 是 |

单元/契约使用本地假服务注入失败；真实站点测试补充覆盖，不把外网不稳定伪装成确定性测试。

## 3. 50 题真实任务集

初始任务分布：软件/插件版本 12、架构选型 8、论文 10、新闻/时效/争议 10、JS/已授权页面 5、长文档/PDF 5。

开发题 30、留出题 20，尽量分层。每题包括目标、日期/版本、需要覆盖的要点、参考来源、可接受推断、明确错误项和数据使用范围。带登录内容或用户私有数据的题目只在授权环境保留，不公开正文或凭据。

v0.1 对未实现专题/浏览器题标记 unsupported，不计成已支持任务成功；同时报告全题集覆盖和已支持子集结果，避免通过缩小分母虚增成绩。

公共基准可补充研究/浏览器任务，但不能替代用户任务。在线评测需要提供方凭据与预算，普通 PR/CI 不自动消耗真实账号。

## 4. 评分口径

分别记录：

- 完成度：关键子问题 solved/partial/unresolved 与参考目标是否满足；
- 事实正确性：主张的对象、日期、版本、单位和条件是否正确；
- 引用支撑：原文是否实际读取、定位有效、语义是否支持主张；
- 检索覆盖/独立性：必要证据是否找到，转载和同源是否重复计入；
- 时效：来源日期与问题要求匹配，不把抓取日期当发布时间；
- 执行：取消、恢复、预算、工具结果与状态是否符合约定；
- 消耗：logical/known/unknown calls、已知 token、金额类型、耗时与内存。

评分采用确定性核验、参考材料/人工抽查与模型辅助相结合。单一 LLM judge、hash 完整性或多个模型一致不能单独证明事实正确。

同题对照记录真实版本、时间、来源权限和预算；重复运行观察稳定性。公开报告不得只挑最好的一次，也不把成本不同或权限不同的结果写成严格公平排名。

## 5. 发布阻断与质量晋级

### v0.1 工程阻断项

类型/构建、bundle 隔离加载、契约和场景表的必需项通过；无未处理的数据破坏、凭据泄露、越权或取消失效问题。发行产物经过实际加载，README 对应实际支持能力。

### 研究质量

样本中发现虚构来源或伪造原文，该任务判失败并阻止据此宣传高质量成绩。确定性关键事实必须有可定位原文支撑；无法支持时降为推断/未知，不以包装措辞强行通过。

覆盖、事实、引用与成本分层展示，不在没有样本和标注前承诺“95% 企业级正确率”。修改默认模型、来源或执行器，需有留出题的增量收益与关键回归检查。

### v0.2 执行器晋级

worker 的进程/权限/目录/取消/资源上限、浏览器 profile 互斥、模型网关与图片/Schema 支持实测；用相同任务与预算比较选择默认，不根据作者宣传倍数直接切换。

## 6. 每次验收记录

应包含：commit/tag、包锁/发行校验、DSH/Node/平台版本、fixture/数据集版本、执行时间、配置摘要、实际来源/模型/执行器、命令或操作步骤、结果与失败、费用口径和剩余限制。

公开样例采用合成/允许再分发的材料；个人 trace、密钥、浏览器 profile 和未获许可的全文不提交到仓库。

## 7. 发布与安装检查单

- [ ] 对照施工任务与实际提交，所有宣称完成项有证据。
- [ ] 更新兼容矩阵、变更/迁移/回退说明和第三方声明。
- [ ] 打包清单不含私有数据或额外运行环境，检查构建后的实际内容。
- [ ] 在干净隔离 profile 安装发行包，验证最小闭环和卸载。
- [ ] 确认目标名称/版本/可见性与发布范围，防止发布错包或覆盖现有版本。
- [ ] Git tag/npm 发布/生产安装分别记录执行与结果；仅有设计文档不表示这些动作已授权或完成。


## 首条研究链路离线基线

运行 `npm run benchmark --silent` 获得逐题 JSON。CI 每次推送运行同一套固定数据，逐题检查候选来源、引文和快照坐标、失败状态、逻辑调用数以及页面预算。当前十题覆盖成功搜索、查询部分失败、版本参数、目标地址限制、空搜索、页面预算、跳转去重、访问受限、中文聚焦和无可读正文。

用例使用合成文本和固定适配器，耗时仅描述本地执行。真实源召回率、文章解析质量、对照路由成本、模型引用支持率以及留出题评估需另行运行。[用例](../benchmark/research-cases.mjs) · [执行器](../benchmark/research-baseline.mjs)
