# DSH 网络接入与抓取管道

本文记录 SourceQuest 的设计决策和 DSH 0.2.2-rc.5 的静态核对结果。实现前用隔离 profile 验证服务选择、权限、工具可见性和产物读取。

| rc.5 已核对 | 对 SourceQuest 的影响 |
|---|---|
| `ctx.web` 提供注册、枚举和释放 Provider 的接口。执行时由配置和宿主选择规则决定使用哪个 Provider。 | 可以保留原生 `web_search` / `web_fetch` 的接口。注册与启用分别管理。 |
| `WebSearchRequest` 是单查询。原生工具会并发执行整个查询列表，任一失败后取消同批工作并抛错。 | Provider 内的降级只覆盖单次查询。逐条保留成功结果由 `net_research` 自己调度，未来可推动宿主支持。 |
| `WebFetchRequest` 只有 URL。原生抓取结果为 HTML 或文本，工具默认输出上限为 200,000 字符。 | 富结构、聚焦参数、段落定位和 Artifact 引用由探原工具承载。原生适配返回有界文本。 |
| 已安装的 HTTP Provider 对协议、URL 凭据、同源重定向和响应体有限制。所查实现把连接交给进程 dispatcher，类型文档提到地址检查与连接固定。 | 仅凭类型注释无法确定部署的 DNS 和出口行为。SourceQuest 自有 HTTP、文档、爬虫和浏览器路径统一执行出站策略。 |
| `ctx.spillStore` 有按会话保存完整文本的接口，返回 locator 和读取提示。 | 核对当前 profile 是否提供该服务及其读取、保留周期。持久证据仍按任务的 ArtifactStore 契约管理。 |

核对依据为宿主安装的 rc.5 包，包括 [dsh-web](https://www.npmjs.com/package/@deepseek-ai/dsh-web/v/0.2.2-rc.5)、[dsh-tool-web](https://www.npmjs.com/package/@deepseek-ai/dsh-tool-web/v/0.2.2-rc.5)、[dsh-web-fetch-http](https://www.npmjs.com/package/@deepseek-ai/dsh-web-fetch-http/v/0.2.2-rc.5) 和 [dsh-spill](https://www.npmjs.com/package/@deepseek-ai/dsh-spill/v/0.2.2-rc.5)。Creator Mode / tool-cordis 用于实验环境验证运行时与作用域。打包命令和本地路径安装语法以目标版本 CLI 帮助与实测为准。

## 两层接入

- 默认复用宿主 `ctx.web` 和已有搜索管理器，保持当前 Provider 选择。
- 可显式选择 SourceQuest Search / Fetch Provider，分别启用。原生 Provider 调用独立的后端端口。SourceQuest Provider 的内部调用禁止再次进入包含自身的宿主选择链。若管理器无公开的共存方式，原生模式仅在独立配置下启用。卸载仅恢复仍由插件拥有的选择项，保留用户后续改动。
- `net_research` 和 `net_job` 负责完整研究任务。多查询各自返回成功、无结果、失败或取消状态。允许部分成功并保留证据。取消和总预算对所有子调用生效。
- 进阶工具拟提供 `web_extract`、`web_map`、`web_crawl`、`feed_fetch`。如宿主已有同名工具，采用项目命名空间。工具按配置与作用域注册，能力缺失时给出诊断。订阅读取和定期调度分开。
- 原生模式沿用宿主工具 Schema，适用于已挂载相应工具和服务的预设。各预设的可见性及新增工具对模型输入和缓存的影响应实测。

## 搜索与抓取

搜索适配按语言、主题、明确过滤条件、可用凭据和预算选择后端。SearXNG、Tavily、Exa、Brave 与站内接口按实际来源登记。同源去重后按来源排名融合。超时、限流和缺少权限分别处理。总 deadline 覆盖重试和降级，进程内 LRU/TTL 缓存按来源、约束和访问身份隔离，只有等价请求且在时效窗口内才可复用。

| 阶梯 | 行为 | 升级条件 |
|---|---|---|
| L1 HTTP | 有界静态读取，提取正文、标题和链接。优先比较 Readability 与 Defuddle，复杂表格可保留原始结构或定位。 | MIME 指向其他解析器，或正文质量不足。短文本结合任务判定。 |
| L2 专项解析 | PDF/DOCX、结构化 API、JSON/XML/Feed 分流。GitHub REST 优先取结构化数据。字幕仅通过可用且已授权的接口。公开页面可按配置使用 Jina 或 Firecrawl。 | 有明确动态渲染需求且允许使用浏览器。 |
| L3 浏览器 | 按需启动隔离的 Playwright worker。按目标元素或正文信号判断就绪，受共享 deadline 约束。可评估复用宿主浏览器服务。 | 权限缺失、验证码或挑战页返回明确状态，403 不自动触发浏览器。登录读取使用用户明确授权的专用会话。 |

每步记录抓取方式、最终 URL、内容状态和失败原因。前一步识别到 PDF/API 等明确类型可直接分流。认证、访问策略拒绝、限流与真实 JS 空壳分别处理。账号内容不得自动交给第三方 Reader。

## 上下文与出站边界

- 模型只收到标题、目录、短摘要和定位片段。字符阈值初始可试 15,000，另设最终输出 token 上限与兼容字符上限。聚焦提取按章节分块，首期评估 BM25 或关键词排序，验证中文分词与定位。结构化提取区分可定位字段与缺失字段，并校验 Schema。
- 全文落盘以策略允许且实际获得的内容为限。返回会话受权的 Artifact 引用、读取提示和截断状态。原生 Seam 缺少可信 owner 时只返回有界内容，避免依靠全局状态猜测会话。持久快照提交成功后才显示引用。
- 默认公开目的地。在每次实连及跳转前约束目的地与访问身份，确保解析检查与实际连接的目的地一致。浏览器子资源和代理出口一并受约束，普通域名白名单不会覆盖目的地安全策略。私网读取如需支持，作为独立的管理员显式配置能力，单独验收。
- 按目标主机与供应商限流，退避和熔断共享任务预算。站点采集遵守范围、robots 策略、页数、深度和并发限制。外部内容作为数据处理。凭据经宿主解析并按来源限定，XML/文档解析禁用不需要的外部资源访问。
- 注册、缓存、计时器、连接池和浏览器工作进程绑定插件生命周期。热重载与卸载验证旧任务取消、子资源释放与 Provider 清理。

首发优先交付兼容接入、逐查询容错、L1、摘要与 Artifact。验证原生 Provider 选择和既有管理器共存后再列为受支持模式。L2/L3 与高级工具按后续施工批次逐项验收。

协议发现、多模态证据和用户主动订阅见[高级获取路线](ADVANCED_RETRIEVAL.md)。该路线扩展执行器选择，沿用本文件的出站和访问控制。
