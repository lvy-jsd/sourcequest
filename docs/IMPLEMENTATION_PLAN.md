# SourceQuest 施工计划

计划版本：1.3 · 2026-11-19（Australia/Perth）。

状态：可执行的设计计划，尚未开始代码实现。本文的任务、测试和发布门槛均为待完成项，不能作为已经具备能力的证明。

## 1. 已确定的约束

- 独立开源项目，DSH 原生插件首发；保持单仓库、单主包、内部模块化。
- 面向个人高标准研究，优先质量、证据、自动调度与可靠任务。
- 复用宿主来源、模型、凭据和任务接口；保留手动指定，不要求切换现有会话模式。
- 主包不隐式安装浏览器/Python、不启用新付费服务；可选执行器独立管理。
- 现有生产环境不作为开发沙箱。安装、部署、npm 发布另有步骤和记录；完成文档不表示这些动作已执行。
- 初始宿主验证目标为 DSH `0.2.2-rc.5`；正式支持范围由测试决定。不能用最新 upstream main 代替锁定发行包。
- 不把个人账号、模型组名、域名、机器路径或私有研究记录写进公开默认值。

项目中的角色是工作责任，不预设多人团队：维护者负责契约与合入；贡献者实现任务；评测复核者按参考材料检查结果。同一人可以承担多个角色，但发布需保留检查记录。

## 2. 首期边界

### v0.1 必须完成

1. 标准 DSH bundle、诊断与卸载，基础功能不要求 Magpie 或 Tool Ultra。
2. 两个按需入口：`net_research`、`net_job`，以及原生策略/任务/证据面板。
3. 已知链接读取、普通搜索、有限子问题与补查；任务预算和三层路由。
4. 统一证据、关键结论定位、可见的缺口和失败；短任务直接结果，长任务可管理。
5. 持久检查点、取消和中断后恢复；宿主 jobId 与持久 taskId 分开。
6. 开发题、留出题、集成测试和失败记录；明确兼容矩阵与已知限制。

### 后续阶段

- v0.2：高级专题连接器、动态抓取、浏览器/PDF 执行器、深入研究与复核。
- v0.3：MCP/CLI 与跨客户端共享任务。

全部候选组件进入能力路线图；每个发行版只宣传经过实现和验证的子集。首期不引入多租户、集群或独立聊天应用。

## 3. 代码与依赖边界

```text
src/
  core/                 # planner/router/budget/task/evidence/result
  ports/                # SearchPort/ReadPort/LlmPort/TaskStore/ArtifactStore
  adapters/dsh/         # SDK、来源、模型、credentials、jobs、storage、RPC
  connectors/           # 已验证的专题能力及发现
  client/               # DSH 原生设置、进度与证据视图
schemas/                # 版本化数据契约
workers/                # 后续可选进程协议与实现
fixtures/               # 合成/获准发布的固定数据
test/                  # 实现时按 unit/contract/integration 分层
evals/                 # 题目清单、评分定义、运行清单、脱敏结果
```

依赖方向：client → DSH adapter → core/ports；连接器实现 ports；core 不导入 DSH、React 或具体网络供应商 SDK。

DSH/Cordis/客户端 SDK 使用宿主匹配实例并 external/peer 处理，不捆绑第二套服务。生产包只包含构建产物和必要资源。主包的构建工具、Schema 库、Node/包管理器版本在 G0 锁定，CI 使用同一锁文件。

专题能力无法由普通 `ctx.web` 表达时使用明确适配器；不能把未知日期/topic 参数塞进普通接口后声称约束生效。

## 5. 自动路由的施工细则

按顺序实施：

1. **硬约束过滤**：用户指定、权限/凭据、topic、日期/域名、输入模态、上下文、来源开关。
2. **资源可行性**：已知额度、并发、剩余预算、冷却及执行器是否就绪。
3. **策略排序**：质量档位、可复查的离线表现、近期成功/耗时样本。样本不足标记 unknown，使用明确默认顺序，不制造精确质量分。
4. **有限计划**：为每步登记预期证据目标与预算；有已知 URL 时直接读取。
5. **结果驱动升级**：空壳→渲染、PDF→解析、登录→需要用户动作/有权限浏览器、证据不足→定向补查。
6. **记录决定**：policyRevision、候选与拒绝原因、选中能力、实际执行结果。仅保存可解释的简短理由，不要求保存模型内部推理。

手动指定不可用时解释原因；只有请求明确允许 fallback 才切换。来源路由不得同时改变全局默认模型，模型路由不得隐式打开付费来源。

## 6. 工期与推进规则

当前没有实现基线，不承诺日历完成日。以 G0–G6 的交付门推进；G0 完成后按实际 SDK 适配量给出估时和风险缓冲。网络/凭据/平台验收缺失应明确标为受阻项，不宣称完成。

每个任务的完成记录包含：提交、验证环境、命令/场景、结果、局限。协议/持久化变更先更新契约与迁移，普通实现变更附必要验证。提交聚焦可审查的工作；按项目协作约定正常推送，不 force push。
