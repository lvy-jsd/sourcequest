# 架构设计

以下为规划结构，尚未对应已实现模块。

```text
DSH 会话与原生面板
        │
DSH 适配：工具 / 模型 / 凭据 / 存储 / jobs / RPC
        │
研究核心：规划 / 路由 / 预算 / 证据 / 任务状态
        │
来源连接器与可选执行器
```

## 模块

- `core`：任务、策略、预算、证据和结果，不导入 DSH SDK。
- `adapters/dsh`：调用宿主公开接口，绑定会话与任务所有者。
- `connectors`：来源能力、约束、认证引用、状态与结果规范化。
- `client`：DSH 中的来源、策略、任务与证据视图。
- `workers`：按需启动的浏览器、动态抓取和文档解析组件。
- `schemas`：版本化的任务、证据、事件和适配器协议。

首期只发布一个主插件包。MCP/CLI 出现实际复用需求后再拆分独立包。

## 路由

先处理 URL、专题、日期、来源指定等明确约束，再匹配可用能力和预算。只有任务分解或复杂判断需要时才调用模型。正文不足、过期、冲突、登录和动态渲染需求分别处理。

模型、搜索源与执行器是三层选择，各自记录真实调用结果。额度未知时明确标记；用户的显式选择不能被无提示替换。

## 任务与证据

拟提供 `net_research` 与 `net_job` 两个小入口。持久 taskId 与宿主进程内 jobId 分开；宿主重启后核验检查点再恢复。

证据最少包含来源身份、请求/最终 URL、抓取时间、可得的发布或版本信息、内容散列、原文定位与实际提取方式。正文和附件独立存放，模型按需读取相关片段。

## 集成原则

普通搜索优先复用宿主及现有管理器。新插件不再把自身聚合器注册回同一搜索路径，避免递归与重复请求。

可选组件缺失时保留基础能力，诊断具体缺口。DSH/Cordis SDK 使用匹配宿主的实例，正式兼容范围由集成测试决定。

不固定个人账号、文件路径、模型组、域名或运行环境。密钥通过宿主引用解析，凭据、私有网页、浏览器状态与真实个人 trace 不进入公开样例。
